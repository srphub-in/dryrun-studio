Why it helps

A safer path from your edits to a live site.

Dry Run Studio turns your release process into a clear, guided workflow. It prepares an isolated copy of your project, keeps your working folder untouched, checks for common issues, and runs your production build locally before anything is sent to GitHub or Cloudflare Pages.

When the checks pass, review the exact file changes, stage and commit your work, then push from the same window. Dry Run Studio follows the Cloudflare Pages build and streams its progress and logs, giving you a clearer view of what is being published—from the first local check to the live site.

How it works

Why build in an isolated local sandbox before deploying?

Triggering a cloud deployment just to verify whether a production bundle compiles wastes CI minutes, pollutes your Git commit history with trial-and-error fixes, and slows down feedback loops. Conversely, running npm run build directly inside your active repository generates dist/ clutter and locks files while you are still working.

Dry Run Studio separates editing from verification. It delta-syncs your modified files into an isolated scratch directory, links your existing node_modules in milliseconds via Windows NTFS junctions, and runs a full production build and route audit locally. Your source folder stays 100% untouched, and only verified, working code ever gets pushed to GitHub and Cloudflare Pages.

What’s inside

Six parts that handle the steps between “saved the file” and “it’s live”.

01 / SANDBOX

A scratch folder, not your repo

Your source is synced to a separate sandbox directory, and cached dependencies are linked in through Windows junctions. Your repository folder stays clean.

02 / DIFF ENGINE

A baseline that moves with you

Modified, added and deleted files are tracked against your last working build. After a successful cloud deploy, that build becomes the new baseline automatically.

03 / VERIFICATION

Pre-flight and smoke tests

Before building, it scans for exposed API keys, merge conflict markers and leftover debugger; statements. Afterwards it checks every built HTML route for broken local links.

04 / DIAGNOSTICS

Error reports in Markdown

Compiler stack traces, JavaScript errors from the live preview, missing assets that return 404, and bundle sizes all go into a single .md report.

05 / SECURITY

Credentials stay on your machine

Each repository’s GitHub remote and Cloudflare API token are stored locally, encrypted with Windows DPAPI and tied to your user account.

06 / DEPLOYMENT

Push, then watch the build

Stages, commits and pushes multi-file changes to GitHub, then streams the Cloudflare Pages build stages and logs in the same window.
